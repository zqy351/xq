# 中国象棋 · 双人同屏 / 人机对战

一个零依赖、零构建、可直接双击打开的中国象棋网页游戏。核心模式是**同一设备双人同屏**，同时提供三档难度的人机对战。

- 纯原生 JavaScript，不使用任何框架、构建工具或 ES Module
- 不依赖任何外部资源（字体、图标、脚本全部可选或内联），断网也能完整运行
- 棋盘与棋子全部由 Canvas 程序化绘制，无一张位图素材
- 规则完整：7 种棋子走法、九宫、象眼、马腿、炮架、兵过河、自将与照面过滤、绝杀、困毙、长将判负、三次重复、60 回合自然限着
- AI 在 Web Worker 中搜索，主线程不掉帧，困难档 1.5 秒内必出招

## 快速开始

### 方式一：直接双击

打开 `index.html` 即可。全部脚本按传统 `<script>` 顺序加载并挂在 `window.Chess` 命名空间下，`file://` 协议下可正常运行，无需服务器。

### 方式二：本地静态服务

```bash
python3 -m http.server 8000
# 浏览器访问 http://127.0.0.1:8000/index.html
```

## 操作说明

| 操作 | 说明 |
| --- | --- |
| 选中棋子 | 点击（或触摸）己方棋子，抬起并显示出所有合法落点 |
| 走子 | 点击任一高亮落点。点到非落点位置会取消选中 |
| 取消选中 | 再点一次同一棋子，或右键点击棋盘 |
| 新局 | 面板「新局」，随时可点（会中止正在思考的 AI） |
| 悔棋 | 双人同屏回退 1 步（弹层确认）；人机对战回退 2 步（你的 + AI 的） |
| 自动翻转 | 开启后，轮到黑方时棋盘 180° 旋转到黑方视角，翻转完成后才接受落子 |
| 音效 | 开关落子与吃子的 Web Audio 合成音效 |
| 计时 | 开启双人计时，每方 10 分钟，用完即判负 |
| 快捷键 | `N` 新局 · `U` 悔棋 · `F` 切换自动翻转（桌面端） |

## 功能清单

**对局模式**
- 双人同屏（默认）：两人轮流在同一设备落子，回合提示带色块与脉冲高亮
- 人机对战：玩家默认执红；可勾选「AI 执红先行」交换阵营
- 三档难度：简单（深度 2 + 同分随机）、普通（深度 4 / 400ms）、困难（深度 6 / 900ms）

**规则完整性**
- 车：直线任意格，途中不得有子
- 马：日字，蹩马腿判定
- 象/相：田字，塞象眼判定，不得过河
- 士/仕：九宫内斜走一格
- 将/帅：九宫内直走一格；将帅不得照面（同列且中间无子）
- 炮：直线移动；吃子必须恰好隔一个炮架
- 兵/卒：未过河只能前进；过河后可左右平移，不可后退
- 统一过滤：任何走法只要导致己方被将军或双方照面，即视为非法（不是只挡一部分）
- 终局
  - 绝杀：对方被将军且没有任何合法应将走法
  - 困毙：对方未被将军，但已无任何合法走法
  - 长将判负：一方连续将军把局面逼成三次重复，判长将方负（标准中国象棋规则）
  - 三次重复：双方均非长将的重复局面，判和
  - 自然限着：连续 60 回合（120 个半回合）无吃子判和
  - 超时：开启计时后一方读秒耗尽判负
- 将军提示：走子后被将军的一方，回合栏转红并提示「必须应将」，走法列表只保留能解将的选择

**界面**
- 棋盘：木纹底板、双线外框、九宫斜线、楚河漢界、兵位与炮位十字花刻度
- 棋子：投影 / 侧壁厚度 / 顶面径向渐变 / 双圈描边 / 材质纹理 / 浮雕文字 / 高光暗部 七层绘制
- 走棋记录：中文记谱（红方汉字列号从右往左、黑方数字列号从左往右），自动滚动到最新
- 移动端：375px 宽可完整操作，交叉点间距不低于 34px，无横向滚动条
- 所有提示走页面内 toast 与弹层，不使用 `alert` / `confirm` / `prompt`

## 目录结构

```
chinese-chess/
├── index.html            入口页（只负责 DOM 结构，不写业务逻辑）
├── style.css             布局、面板、按钮、弹层、toast
├── README.md
├── LICENSE
├── .gitignore
├── src/
│   ├── namespace.js      window.Chess 命名空间 + 通用工具（缓动、固定种子随机、离屏画布）
│   ├── rules.js          规则引擎：走法生成、合法性过滤、将军检测、记谱
│   ├── game.js           对局状态机：落子、悔棋、重复局面、限着、计时、胜负
│   ├── ai.js             评估函数、迭代加深 Alpha-Beta、置换表、静态搜索、Worker 桥接
│   ├── render.js         Canvas 渲染：棋盘烘焙、棋子贴图烘焙、动画、翻转、命中测试
│   ├── audio.js          Web Audio 合成音效
│   └── ui.js             交互编排：选中、落子、按钮、弹层、记录、响应式尺寸
└── tests/
    ├── rules.test.js     规则自测（含反向将军检测 vs 暴力枚举的交叉验证）
    └── ai.test.js        AI 自测（评估对称性、战术、搜索速度）
```

### 模块职责边界

- `rules.js` 不依赖 DOM，只处理棋盘数组，可被 Node 直接加载测试
- `rules.js` 内所有函数都写成命名函数表达式并通过 `R.xxx()` 互相调用，因此 AI 的 Worker 能用 `toString()` 把同一份规则源码注入，**走法生成 / 搜索 / 胜负判定共用唯一一套过滤逻辑**，不会出现两处实现不一致
- `game.js` 依赖 `rules.js`，管理对局状态与历史快照
- `render.js` 只读状态、只画图，不修改棋局
- `ui.js` 是唯一的编排层，串起 Game / Renderer / AI / Audio

## 测试

```bash
node tests/rules.test.js
node tests/ai.test.js
```

- `rules.test.js`：46 项断言。包含 3000 个随机局面 × 双方 = 6000 次「反向射线将军检测」与「暴力枚举全部伪走法」的交叉验证，要求 0 不一致。
- `ai.test.js`：14 项断言。包含红黑评估对称、吃掉无保护子、不白送马、一步绝杀、40 步自对弈合法性、Worker 源码可生成、困难档耗时上限。

## 部署到 GitHub Pages

1. 新建仓库并把本目录推上去：

```bash
git init
git add .
git commit -m "feat: 中国象棋 双人同屏 + 人机对战"
git branch -M main
git remote add origin https://github.com/<你的用户名>/<仓库名>.git
git push -u origin main
```

2. 打开仓库 `Settings → Pages`，`Source` 选择 **Deploy from a branch**，分支选 `main`，目录选 `/ (root)`，保存。
3. 等 1–2 分钟，访问 `https://<你的用户名>.github.io/<仓库名>/`。

由于全部资源使用相对路径、无构建产物，无需任何额外配置即可部署。若要自定义域名，在仓库根目录加 `CNAME` 文件即可。
